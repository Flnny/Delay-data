# 2026-11-11 — Tabular ablations: shared runner, fixes and re-run

Branch `ablation-fixes` compared with `main`.
`main` @ d160b96 (2026-11-05) → `ablation-fixes` @ 28c71eb (2026-11-11) · 19 commits · 141 files changed, 73170 insertions(+), 1700 deletions(-)

## 1. Summary

All tabular ablations were rebuilt on one seeded, verified protocol and run again. The old
code had several bugs that directly distorted the results; they are fixed, so the old
results on `main` cannot be compared with the new ones. The new results cover 10 feature
sets × 7 models × 3 seeds × 2 training sizes, all measured on the same 2,547,088 test rows
(419 of 420 cells complete).

**Main findings**

- **For the strong models, the amount of training data is the largest effect.** Fitting the
  final model on all of train instead of 10% adds 2–5 AUC points (XGBoost 0.644 → 0.683).
- **GBDTs are the strongest models.** On every feature set the best GBDT at least matches the
  best deep model; the best result is XGBoost at ≈0.683, identical on all features, SHAP
  top-10 and SHAP + HUIM.
- **The HUIM pattern columns add no measurable signal.** Adding patterns to the same SHAP
  features (03 − 02) does not move the best models, and HUIM alone (04) is the weakest arm.
  The old "SHAP + HUIM adds 1–2%" came from the bugs that were fixed.
- **Ten SHAP features keep almost all the signal**, and with all of train they clearly help
  the deep models (FT-Transformer 0.651 → 0.674).
- **Patterns mined on another year (2024) transfer poorly to 2020.**
- **Noise:** seed-to-seed std is mostly 0.001–0.010 (up to 0.016 for some all-of-train
  cells), while the DeLong standard error is ≈0.0002, so differences must be judged against
  the seed std.

## 2. Starting point: the state of `main`

On `main` the ablations ran from eight separate, copy-pasted `run.py` files:

- 02 (SHAP only) had never been run; 02/03 read a `SHAP_HUIM/` directory that did not
  exist, and 04 read the 2024 extraction directly.
- SHAP and HUIM were mined on 2024 only, while the models were trained and tested on 2020.
- 01 (the reference) was trained with different settings from the other arms (data
  fraction, batch size, patience), so the comparison was biased.
- Every cell was a single run; the result files recorded no seed, target or test-set identity.
- There was no GBDT comparison, and FT-Transformer was only in 01.

## 3. Bugs found and fixed

Each of these changed the results. All are fixed; library bugs are patched and the patches
are verified to leave everything else unchanged. Details: `exp/Tab_exp/ablations/common/README.md`.

| Bug | Effect | Fix |
|---|---|---|
| The hyper-parameter search never searched (mambular `set_params` does not rebuild the config) | Every candidate and every final model trained the defaults | Candidates are built from scratch |
| AUC was computed from hard labels | The value is really balanced accuracy; a constant predictor read 0.500 | AUC from probabilities |
| LabelEncoder fit separately on each split | The same airport got different codes in train and test | Encoders fit on train only |
| pretab PLE encoding depended on the batch (last threshold clamped to the batch max) | A flight's encoding changed with its neighbours; SHAP was affected too | Patched; otherwise identical output |
| mambular FT-Transformer attended across rows | O(batch²) memory, predictions tied to batch-mates | Batch-first attention patch |
| 2024 HUIM patterns sorted alphabetically (PAMI returns utilities as text) | The "top 20" were not the 20 highest | Numeric sort in the 2020 extraction |
| KBinsDiscretizer fit bins on a random 200k-row subsample | HUIM bins changed between runs | Exact quantiles (`subsample=None`) |
| `FL_DAY` used as a feature | Test days never occur in train; a meaningless column | Split key only |
| Categorical type depended on sample size (`OP_CARRIER_FL_NUM`) | Numeric at 10%, categorical on full data | Type fixed (`cat_cutoff`) |
| Memory leak during long searches | ~1 GB growth per hour | `gc.collect()` after each fold |

## 4. What was added

**Infrastructure**

- **Shared, seeded runner** (`exp/Tab_exp/ablations/common/`): one `base_config.yaml`; arms only
  define their feature set. CLI: `--seed --target --models --reuse-params --set --out-dir`.
- **Target option**: `abs` (|delay| > 15, default), `late`, `3class`.
- **Extended `results.csv`** and a **`test_hash`**: an arm that evaluates on a different test set fails.
- **Two-phase protocol**: search on 10% of train (10 candidates × 3 folds, ROC-AUC); final fit
  on 10% or 100%; extra seeds reuse the stored search.
- **GBDT baselines**: LightGBM, XGBoost, CatBoost (native categoricals for CatBoost), same search budget.
- **Safe parallel runs**: locked writes, job-claim markers, a memory watchdog.
- **Speed**: batched data loading (~28× faster inference) and chunked test prediction; both give identical results.
- **Analysis**: `aggregate.py` (all tables + a `RESULTS.md` per arm), `paired_test.py` (paired DeLong), `check_configs.py`.

**Arms and data**

- **01b**: all features, trained exactly like the other arms — the new reference.
- **2020-train SHAP + HUIM extraction** (`exp/Tab_exp/shap_huim_extractions/02_2020_train`): mined on
  2020 training days only; now the default. The 2024 extraction remains as an other-year check.
- FT-Transformer in every arm; the 06 / 06.1 / 06.2 LLM arms moved to the new runner.
- The representation ablation grouped under `ablations/representation/`; skrub + LightGBM and
  raw + CatBoost rows added to the bake-off.

**Documentation**

- A stand-alone README in every arm folder (question, feature set, config, how to run,
  findings) and a generated `RESULTS.md`.
- `ablations/README.md` as the entry point, `common/README.md` for the runner and the bug
  list; `.claude/rules` updated; the handoff page on claude.ai rewritten.

## 8. Open issues and recommendations

- **Primary training size:** the arms default to a final fit on 10% of train. All of train
  adds 2–5 points and changes some orderings; decide which one the thesis reports as the
  main result (recommendation: 100%).
- **Incomplete cell:** FT-Transformer, 03, all of train (2 seeds). The selected configuration
  (10 layers, lr 1e-3) looks unstable on the full data; it could be retried with a lower
  learning rate (to be reported as a deviation from the protocol).
- **TabFM on 2020:** TabFM leads clearly on the 50k sample; running the same comparison on the
  2020 ablation split would settle the direction. The TabPFN embedder is still not evaluated (licence).
- **Merge:** the work is on the `ablation-fixes` branch of the fork; no pull request to `main` yet.
- **The role of HUIM in the thesis:** as it stands the pattern columns do not improve
  prediction. The method's value could be positioned around interpretability (which
  combinations of conditions are associated with delay).
